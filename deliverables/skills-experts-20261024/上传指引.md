## 一、上次报错的根因

**不是包里缺 SKILL.md，是上传错了包类型。**

| | 插件包（错） | 技能包（对） |
|---|---|---|
| 结构 | `自洽AI工程坊/{plugin.json, agents/, skills/{skill}/SKILL.md}` | `{skill-name}/SKILL.md + references/` |
| 顶层有 SKILL.md | ❌ **没有**（在 `skills/` 下面） | ✅ 有 |
| 平台能否识别 | ❌ 报「未找到 SKILL.md」 | ✅ 生成技能ID |

平台解包逻辑（复刻自客户端 `resolveExtractedSourceDir`）：
```
解包 → 根目录若恰好 1 个目录条目就钻进去 → 在该层找 SKILL.md → 找不到就报错
```

**关键**：平台的「添加技能 → 创建技能」入口**一次只吃一个技能包**，上传后自动开包解析并生成技能ID。
整套专家团插件（10 技能 + 路由专家）是**另一条路径**（专家插件上架，需 plugin.json + icon + 双语展示字段）。

## 二、两种形态（都在桌面上）

### 形态 A：集成技能（推荐先传这个）

**文件**：`self-consistent-ai-forge.zip`（44.8 KB，22 个文件）

一个包承载全部能力。主 `SKILL.md` 承担**路由**（把用户表达映射到八步链路的某一阶段），
21 份参考文档放在 `references/` **按需加载**（一次只读当前阶段那一份）。

| 优点 | 说明 |
|---|---|
| 一次上传 | 用户只需上传 1 个包，不必传 10 次 |
| **保留链路关系** | 八步一闭环是这套方法学的核心，拆成 10 个独立技能会把链路切��� |
| 触发更准 | 用户说「帮我造个企业 AI 应用」直接命中总控；拆开则 10 个都可能不触发 |
| 知识零损失 | 10 个子技能正文**逐字节哈希一致**（已实测校验），二级 references 10/10 全覆盖 |

**代价**：单包 44.8 KB（vs 单技能 3–6 KB），但平台无大小上限压力。

## 三、操作步骤

1. 打开平台 → 【添加技能】→【创建技能】
2. 选 `self-consistent-ai-forge.zip` 上传
3. 平台开包解析 → 生成技能ID → 填名称/描述 → 保存

**文件位置**：桌面 `技能包-自洽AI工程坊-集成版/`

## 四、上传前自检（别再靠上传试错）

```bash
python ~/.zongyuan_root/tools/skill_zip_precheck.py --dir <zip所在目录>
```

该工具**复刻平台解包逻辑**，上传前就能判定：
- SKILL.md 是否在平台期望的位置
- 根目录是否有多个条目（平台无法确定钻哪一层）
- 是否误传了插件包（该层有 plugin.json 时会明确提示）
- frontmatter 必填字段、重复键
- 子资源目录是否符合约定
- 正文 `@references/` 引用是否命中

实测：旧插件包 → **FAIL 并指出「这是插件包不是技能包」**；11 个新包 → **11/11 PASS**。
